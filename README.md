# TicTacToe (Ktor WebSockets)

A two-player tic-tac-toe game over WebSockets, built with Kotlin Multiplatform and Ktor. The Ktor server and the browser client share the same domain rules and JSON wire protocol, so every state change is broadcast to both players and to spectators from one source of truth. Beyond a bare board there are rooms and invite links, configurable boards and clocks, practice bots, Elo-rated profiles, shareable replays and an installable PWA.

## Run

```bash
./gradlew jvmRun       # builds the JS client, listens on :8080, PORT env overrides
```

Then open http://localhost:8080/ to play in the browser (the page is rendered with the Ktor HTML DSL, the client is a Kotlin/JS bundle). Invite friends with a room link: http://localhost:8080/?room=alpha (the quick-play button generates one for you). Append `&lang=en` to any link for the English UI — without the parameter the UI follows the browser's own language (`Accept-Language` on the server, `navigator.language` in the client) and falls back to Russian. Round results persist to `data/scoreboard.json` (override the path with the `SCOREBOARD_FILE` env var; point it at a `.db`/`.sqlite` path to switch to the SQLite store, which keeps one JSON `PlayerStats` blob per player and migrates older normalized rows on first open).

For a container build: `docker build -t tictactoe . && docker run -p 8080:8080 -v "$PWD/data:/app/data" tictactoe`. `./gradlew fatJar` produces the same runnable jar locally (`java -jar build/libs/*-all.jar`); the server reads the JS bundle from `build/dist/js/productionExecutable`, so keep that directory next to the working directory.

### Configuration

| Env var | Default | Meaning |
| --- | --- | --- |
| `PORT` | `8080` | HTTP/WebSocket port |
| `SCOREBOARD_FILE` | `data/scoreboard.json` | JSON store, or `.db`/`.sqlite` for SQLite |
| `LOBBY_FILE` | `data/lobby.json` | named rooms and key-owned names that survive a restart |
| `MAX_GAMES` | `100` | live games in the lobby |
| `MAX_SPECTATORS` | `20` | spectators per game |
| `MAX_CONNECTIONS_PER_IP` | `8` | live sockets from one address |
| `MAX_CONNECTIONS` | `400` | live sockets in total |
| `ALLOWED_ORIGINS` | _(empty)_ | comma-separated extra browser origins; `*` disables the check |

Numbers are clamped to sane ranges, and only well-formed `http(s)://host` origins are accepted. Browser clients must come from the same host as the request (or an allowed origin); behind a TLS proxy set `X-Forwarded-Proto` / `X-Forwarded-Host`. Non-browser clients send no `Origin` and stay allowed. `GET /health` is a cheap liveness probe (`ok`); `GET /ready` answers `{"status":"ok","games":…,"pendingGrace":…,"connections":…}`.

## Features

- **One codebase, two targets:** `commonMain` holds the rules, the bot brain, Elo and the wire protocol; `jvmMain` is the Ktor server, `jsMain` the browser client. Both sides compile from the same types.
- **Installable PWA:** `/manifest.webmanifest` with an SVG icon and generated 192/512 PNG icons, a versioned `/sw.js` that precaches the app shell, cleans stale caches, offers an update prompt and an install button, plus an `/offline` fallback page. Playing still needs the server; reconnecting is bounded (ten automatic attempts, then a manual retry).
- **Start playing without a link:** a quick-play button opens a fresh named room with a copy-link button, so the first screen already offers an invite (a direct `/` visit still joins anonymous matchmaking); a create-game form (room, board, win line, turn time, game clock, bot) composes the join URL — the same settings a room link carries; blank fields fall back to the defaults. The header above the board names your side and spells out the board size and win line; spectators are told they are watching. Leaving a live round or resigning asks for confirmation first. The reconnect token lives in `sessionStorage`, so a second tab of the same profile becomes a real opponent instead of stealing the seat. A hidden tab flashes its title, buzzes the phone and raises a system notification when it is your move (permission is asked on the first click).
- **Themes:** dark by default, automatic light theme via `prefers-color-scheme`, with matching `theme-color` meta tags; a manual toggle (auto → light → dark) sits next to the sound button and persists in `localStorage`.
- **Sound and accessibility:** synthesized Web Audio cues distinguish your own move from the opponent's and mark wins and draws; a mute toggle persists in `localStorage`. Cells carry `aria-label`s, the last move stays marked, and the turn timer shows a progress bar. Live regions announce turns, scores, clocks, errors and chat; the countdown sits in its own `aria-live="off"` span, so the polite status region is not rewritten four times a second. The board is a labelled, tabbable grid, replay controls and profile results carry readable names, and placeholders and cell borders meet WCAG AA contrast in both themes. Inputs have accessible names, focus survives board updates, arrow keys walk the grid, cells keep 44px touch targets, and `prefers-reduced-motion` disables the animations. A move list under the board tracks the running game in chess-style notation (`1. X a1  2. O b2`), following takebacks and round resets.
- **Room chat:** text lines (trimmed, flattened, up to 200 characters) reach both players and spectators with the author's name; invalid or too-frequent lines are refused or dropped. Chat and reactions share one broadcast path.
- **Resilient scoreboard:** JSON writes are atomic (temp file + rename). If the file is unreadable, the original is saved as `<name>.corrupt` and a warning is logged before the store starts empty, so the history is not silently lost.
- **Restart-resilient lobby:** named rooms and key-owned names persist to `data/lobby.json` (override with `LOBBY_FILE`), snapshotted every couple of seconds and on graceful shutdown with the same atomic write. After a restart the rooms come back empty and players rejoin by their link to resume the round, score and clocks with a fresh turn budget; anonymous games, live sockets and reconnect tokens are not persisted.
- **Fair play and bounds:** a name belongs to the persistent player key that claimed it (`&key=`, generated once and kept in the browser's localStorage), so nobody can take it — even after its owner goes offline — and change its Elo rating; a claim without a key belongs to the live session only and is freed on disconnect. The lobby caps active games and spectators per room, and the handshake caps sockets per address and in total (see Configuration). A refused join answers `room is full` or `too many connections`; a foreign browser `Origin` is closed with a policy violation. Bot-only and exhibition games are retired once their last human or spectator leaves. These are light-weight identity guards, not user accounts — there are no passwords or registration.
- **Checks:** `./gradlew build` runs the full test suite, ktlint via spotless, detekt (including the JVM type-resolution tasks) and the JS production bundle; GitHub Actions runs the same on every push and pull request, plus a Playwright E2E job (`npm ci && npx playwright install --with-deps chromium && npm run test:e2e`) that builds the fat jar, starts the server and drives real Chromium through a two-player win, a reconnect reload and a bot round.

## Protocol

- Endpoint: `ws://localhost:8080/play` (use `wss://` behind TLS). A browser handshake from a foreign `Origin` is closed with `CloseReason.Codes.VIOLATED_POLICY`; see Configuration for `ALLOWED_ORIGINS`.
- **Rooms / invite links:** connect to `ws://localhost:8080/play?room=<name>` to play with a specific opponent — the first two connections to a room play each other; every further connection becomes a **spectator**: it receives `{"type":"joined","token":…,"symbol":null}` plus the current `state`, sees every later `state`, but any `make_turn`, `request_rematch`, `request_resign` or `request_draw` from it answers `not your turn` (reactions are open to spectators). Spectators do not hold the room: it still ceases to exist once both players have left (after the reconnect grace), so the name can be reused. Room names are 1–32 characters of letters, digits, `-` and `_` (anything else answers `invalid room name`). Add `&spectate=1` to deliberately join as a spectator even before any player has arrived — otherwise the first visitor of an empty room takes the X slot (the flag is ignored without a `room`). Connections without a `room` parameter are matched automatically and stay players-only — they are paired only with a game that has the same `size`, `win`, `bot` and `turn` settings (a joiner whose settings match no waiting game gets a fresh one with its own settings), and a full anonymous pair rejects extra connections with `room is full`. A joiner who carries a `&name=<str>` parameter (1–20 characters after trim; anything longer answers `invalid name` but keeps the session, just unnamed) gets that name claimed like `set_name` would — the page sends its remembered name this way — and anonymous matchmaking then pairs them with the waiting game whose connected players' ratings sit closest to theirs, preferring rated games over anonymous ones; an unnamed joiner keeps the plain first-come pairing. A name another live session owns answers `name is taken` and the join continues unnamed. Add `&key=<secret>` (1–64 characters of letters, digits, `-` and `_`; anything else is ignored and the claim stays ephemeral) to make the claim persistent: the key owns the name across sessions, one key owns one name (claiming a new name frees the old), and a keyed name answers `name is taken` to every other key — even while its owner is offline. The browser client generates the key once, keeps it in localStorage and sends it only in the WebSocket join query, never in the page URL; clearing site data loses the key and thus the claim to the name.
- **Replays:** every finished round's move list is recorded into the named players' history — `/player` responses carry `moves` and `boardSize` per record, and clicking a match in a profile replays it move by move on a mini board. Every replay view also has an autoplay button and answers the arrow keys, plus a share button: the link carries the whole game in its `#r=…` fragment, so it opens the replay on any machine with no server state involved. The fragment is validated before any board is built (length, board size, win length, move count, coordinates and names), so a crafted link cannot hang the tab.
- **Room list:** `GET /rooms` answers `{"rooms":[…]}` — every named room that still holds players, with `name`, `players`, `spectators`, `boardSize`, `winLength`, `botLevel` and `turnSeconds`. The page polls it every 5 seconds, shows the list above the leaderboard and joins a room on click; anonymous games are never listed.
- **Board size:** a game's board is square and is picked by the first connection that creates it — add `&size=<n>` (an integer `3..10`) to the room URL, e.g. `http://localhost:8080/?room=alpha&size=5`; players joining later inherit the existing board whatever `size` they pass. Anything outside `3..10` (or not a number) answers `invalid board size` before joining. Clients should read the board dimensions from the `field` array rather than assuming 3×3.
- **Win length:** the winning line does not have to span the whole board — add `&win=<n>` (`3..boardSize`, default: the full board dimension) for games like 4-in-a-row on a 5×5 board, e.g. `http://localhost:8080/?room=alpha&size=5&win=4`. Anything outside the range answers `invalid win length` before joining. Every row, column and diagonal of either direction counts, including diagonals that start away from a corner. The `state` event reports the winning run as `winningCells` (`[{"x":..,"y":..}, …]`) so clients can highlight it, and carries `winLength` itself, so a client knows the rule without reading the URL.
- **Turn timer:** a player must move within a time budget or forfeits the round to the opponent — add `&turn=<sec>` (an integer `5..600`, default `30`) to the room URL, e.g. `http://localhost:8080/?room=alpha&turn=60`. Anything outside the range (or not a number) answers `invalid turn time` before joining; players joining later inherit the running timer whatever `turn` they pass.
- **Game clock:** for a whole-game budget instead of a per-turn one, add `&clock=<sec>` (`30..3600`, off by default) — each player gets their own chess clock that only drains while it is their turn; the clocks ride every `state` as `clocks` (`{"X":ms,"O":ms}`) and an exhausted clock forfeits the round. A bad value answers `invalid clock` before joining; like the other settings, the budget belongs to the game its creator starts.
- **Series:** add `&wins=<n>` (`1..10`, off by default) to play a match series — the score line shows the goal (`до N побед` / `first to N`), and when a player reaches it the state marks `seriesWinner`; the next automatic reset clears the score and starts a new series. Draws never count toward the target. A bad value answers `invalid wins` before joining; like the other settings, the target belongs to the game its creator starts, and anonymous pairing only matches games with the same target.
- **Practice bot:** add `&bot=<level>` to the room URL (`easy`, `normal` or `hard`; `&bot=1` stays a synonym of `normal`) and the game fills its empty second slot with a bot. `easy` takes an immediate win and otherwise plays random cells; `normal` is an alpha-beta negamax — perfect on 3×3, depth-limited with an open-window heuristic on larger boards; `hard` keeps deepening iteratively within a ~0.9 s search budget and plays the best move of the deepest pass that finished. The bot thinks for ~0.4 s before searching. Humans have priority — a joining human takes the bot's slot and the bot steps aside; when a human leaves, the bot returns. The bot never asks for a rematch, so a human rematch request alone resets the round. An unknown level answers `invalid bot level` before joining. Like `size`, `win` and `turn`, the level belongs to the connection that creates the game. `&bot=2` turns the room into an **exhibition**: both slots are normal-level bots playing each other round after round, every joiner is a spectator and nobody ever displaces them. Because the bot brain ships in the shared code, the page also offers a **hint** button in practice rounds — any round where one side is unnamed, so rated games never get advice; it runs the hard search in a Web Worker and outlines the suggested cell, so even a deep search on a big board keeps the tab responsive.
- In every game the first connection plays `X`, the second `O`, and X opens the first round; every later round is opened by the other side — the reset alternates the opening turn, so one player never holds the first-move advantage. An emptied game (both players left) is retired.
- Client → server: a text frame holding one JSON message with a `type` discriminator:

  ```json
  {"type":"make_turn","x":<col>,"y":<row>}
  {"type":"reconnect","token":"<uuid>"}
  {"type":"request_rematch"}
  {"type":"request_draw"}
  {"type":"request_resign"}
  {"type":"request_undo"}
  {"type":"react","emoji":"👍"}
  {"type":"chat","text":"привет"}
  {"type":"set_name","name":"Дима"}
  ```

  `chat` carries one line of up to 200 characters; blank, overlong and line-break-heavy text answers `invalid chat`. The line is trimmed and its line breaks flattened before it reaches the room.

  `x` is the column and `y` is the row (`0`-based, `0..size-1`). A malformed or unknown message is answered with an `error` event and does not close the session. `set_name` trims the name and accepts 1–20 characters (`invalid name` otherwise); the name must also be unique among the connected players of the game, case-insensitively, and cannot be claimed by another session (`name is taken` otherwise); when the join carried a `key`, the claim survives the owner's disconnects. Names travel in every `state` as `playerNames` (`{"X":"Дима"}`), survive round resets and are dropped when a player disconnects. The browser client remembers the last accepted name in `localStorage` and re-applies it automatically after a reload.
- Server → client: a text frame per event, also discriminated by `type`:

  ```json
  {"type":"state","state":{"field":[["X",null,null],["O",null,null],[null,null,null]],"connectionPlayers":["X","O"],"playerAtTurn":"O"}}
  {"type":"error","reason":"cell occupied"}
  {"type":"chat","from":"X","name":"Аня","text":"привет"}
  ```

  Chat lines reach both players and every spectator; `from` and `name` are `null` for an unnamed side. A repeat inside 0.5 s is dropped quietly.

  A `state` event is broadcast to both players on every accepted move, connection change and round restart. An `error` event (`reason`: `cell occupied`, `not your turn`, `round is over`, `cell out of bounds`, `malformed message`, `unknown token`, `stale session`, `name is taken`, `invalid turn time`, `invalid bot level`, `invalid reaction`, `nothing to undo`, `invalid clock`, `invalid chat`, `too many connections`) is sent only to the player whose action caused it, and a rejected move does not close the session.
  Every field of `state` is always present in the JSON, including defaults (`winningPlayer: null`, `isBoardFull: false`, `playerAtTurn: "X"`) — no omitted-fields special cases.
- Reconnect: right after connecting every player receives `{"type":"joined","token":"<uuid>","symbol":"X"}`. If the connection drops, the player's slot is held for 10 seconds (`reconnectGraceMs`); reconnecting with `{"type":"reconnect","token":"<uuid>"}` rebinds the session to the same game and symbol and answers with a fresh `joined` carrying the reclaimed symbol, followed by the current `state`. After the grace expires the slot is freed (the next joiner takes the symbol) and the token stops working. A client that reconnects with an unknown token stays in the game it was handed on connect. Every `state` also carries `awayPlayers` — the players whose connection dropped but whose slot is still held — announced the moment the drop is noticed; the page shows a plate with the ten-second countdown while its opponent is away.
- A won or full round resets the board automatically 5 seconds later (the opening turn alternates between rounds); the `score` object (`{"X":<wins>,"O":<wins>}`) accumulates across rounds for as long as the same two players stay connected. While the round is over, every `state` carries `roundRestartInMs` (remaining milliseconds until the automatic reset) and, once a player asks, `rematchPlayers` — the client may send `{"type":"request_rematch"}` to reset early, and the board resets as soon as every connected player has asked. Asking while a round is still running answers `round is not over`.
- **Takeback:** the player who made the last move may ask for it back with `{"type":"request_undo"}` — the offer rides `state` as `undoOfferBy`, asking again withdraws it, and any new move kills it. The opponent (the player on turn) approves with the same message: the stone is removed, the turn returns to its maker, and the move leaves the replay. Asking with no moves on the board answers `nothing to undo`, after the round ends — `round is over`.
- **Reactions:** a player or spectator may send `{"type":"react","emoji":"👍"}` — one of 👍 ❤️ 😂 😮 (`invalid reaction` otherwise, and a repeat within a second is dropped quietly). The server broadcasts `{"type":"reaction","from":<symbol|null>,"emoji":…}` to everyone in the game; the page floats the emoji over the board.
- **Draw by agreement:** while the round is still running, a player may send `{"type":"request_draw"}` — the offer rides every later `state` as `drawPlayers`, and asking again withdraws it. The round ends in a draw (the board restarts like after any other round end, no `score` bump) as soon as both connected humans have offered; with a bot in the game a draw cannot be agreed. Every `state` marks such a round with `isDrawAgreed: true`. Asking while the round is over answers `round is over`.
- **Resign:** while the round is still running a player may send `{"type":"request_resign"}` — the asking side forfeits immediately: the opponent takes the round (the `score` bumps like after any other win), the recorded round counts as a rated loss, and the board restarts on the usual delay. Spectators cannot resign (`not your turn`), and asking while the round is over answers `round is over`.
- **Leaderboard and profiles:** every named player carries an Elo rating (start 1000; the step cools with experience — K=40 for the first ten rated rounds, 24 up to twenty, then 16), but a round against an unnamed side — a practice bot — is unrated: it lands in the history and replays, yet leaves the rating untouched. `GET /leaderboard` answers the top ten sorted by rating (then wins, then name); `GET /player?name=…` answers one profile whose `rank` is its 1-based place in the full leaderboard order and whose `history` carries up to 20 records per page (`epochMs`, `opponent`, `result`, `moves`, `boardSize`, `ratingAfter`) — `&page=N` walks further back (up to 200 records are kept; the response marks `page` and `pages` and clamps an out-of-range page) — and whose `opponents` map carries the running head-to-head tally per named opponent. The page offers a search box under the leaderboard: type a name and hit Enter to open that profile, which lists the history (click a match to replay it), pages it with `‹`/`›` buttons, sketches the rating curve over the page's rated rounds, and shows the head-to-head standings. Unnamed players are invisible to both.
## Development

The build is multiplatform: `commonMain` holds the domain rules and the wire protocol shared by both sides, `jvmMain` the server, `jsMain` the browser client.

```bash
./gradlew jvmTest          # integration (websocket flow) + engine tests, including commonTest on the JVM
./gradlew spotlessApply    # format with ktlint
./gradlew build            # tests + spotlessCheck + detekt (fails on violations)
./gradlew fatJar           # one runnable jar with every JVM dependency
```

detekt checks every Kotlin source in `src/`, and `check` also runs the JVM type-resolution analysis (`detektMainJvm` / `detektTestJvm`) for rules that need type information. Every violation fails the build — there is no baseline to hide behind.

The `commonTest` suite runs on the JVM. Browser tests (`jsBrowserTest`) are deliberately disabled in `build.gradle.kts`: they need a Karma/Chrome runner and npm packages from the Kotlin karma fork, which an offline build cannot resolve. Re-enable them only with network access and a headless browser available. The Playwright suite under `e2e/` is separate: it drives the built app over HTTP/WebSocket like a user would — `npm run test:e2e` starts the server itself (or reuses one already listening on :8080 outside CI).

CI runs `./gradlew build` on every push and pull request (GitHub Actions).
